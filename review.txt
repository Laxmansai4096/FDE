2. CONS & CRITICAL ARCHITECTURAL FLAWS (PRODUCTION BREAKAGES)
================================================================================

[FLAW #1] In-Memory Node.js RAM State (Zero Data Persistence)
--------------------------------------------------------------------------------
• Location: server/orders.js (Lines 10-40)
• Issue: Customer orders and stock counts reside in an in-memory JS array.
• Consequence: In Kubernetes or Vercel serverless environments, pods crash or restart
  regularly. Every restart wipes out 100% of customer orders and resets inventory.

[FLAW #2] Inventory Concurrency Race Condition (Double-Selling Risk)
--------------------------------------------------------------------------------
• Location: server/orders.js (Lines 91-94)
• Issue: Stock deduction uses non-atomic synchronous subtraction (stock -= qty).
• Consequence: During a high-traffic flash sale, 20 parallel requests for 1 remaining 
  bottle will all evaluate stock > 0 simultaneously before deduction occurs. 
  Result: 19 customers pay for items that do not exist.

[FLAW #3] Insecure Direct Object Reference (IDOR Vulnerability)
--------------------------------------------------------------------------------
• Location: public/app.js & server/index.js
• Issue: Order cancellation endpoint accepts plain Order IDs (ORD-8821) without 
  validating user session tokens, JWTs, or cookies.
• Consequence: Any user can open DevTools and issue fetch calls iterating ORD-1000 
  to ORD-9999, cancelling every customer order in the company database in seconds.

[FLAW #4] In-Memory 6D Vector Search Loop (Event Loop Blocking)
--------------------------------------------------------------------------------
• Location: server/db.js & server/gateway.js
• Issue: Cosine similarity calculated via synchronous JavaScript .map() array loops.
• Consequence: At 100,000 SKUs, performing matrix multiplication in Node's 
  single-threaded event loop blocks all incoming HTTP traffic for 8-12 seconds.

[FLAW #5] Static Regex Guardrails vs. Zero-Day Multi-Turn Injections
--------------------------------------------------------------------------------
• Location: server/gateway.js
• Issue: Reliance on keyword matching and basic Base64 decoding.
• Consequence: Adversarial attackers bypass regex via multi-turn context smuggling, 
  nested prompt translation, or unstructured review injection.

[FLAW #6] Internal Infrastructure Telemetry Leakage to Client Browser
--------------------------------------------------------------------------------
• Location: server/gateway.js & public/app.js
• Issue: Internal gateway routing traces and replica node names are passed directly 
  in HTTP response payloads to the client browser DOM.
• Consequence: Attackers inspect node names (gemini-1.5-flash-ap-south) to launch 
  targeted Denial-of-Service (DoS) attacks on specific upstream replicas.

[FLAW #7] Missing Distributed Tracing (No W3C Trace Context)
--------------------------------------------------------------------------------
• Location: server/telemetry.js
• Issue: Telemetry logs lack correlated X-Request-ID or traceparent headers.
• Consequence: When a multi-step workflow fails (Gateway -> ReAct Agent -> OMS DB), 
  engineers cannot correlate disparate log entries to diagnose the root cause.

[FLAW #8] Missing Circuit Breaker Synthetic Canary Probes
--------------------------------------------------------------------------------
• Location: server/gateway.js
• Issue: Circuit breaker trips between OPEN and CLOSED without automated synthetic 
  canary health probes.
• Consequence: Once tripped OPEN, system remains on backup providers indefinitely 
  until manual developer intervention, missing primary provider recovery.

3. STEP-BY-STEP ENTERPRISE FDE PRODUCTION ROADMAP
================================================================================

Phase 1: Persistent Storage & Distributed Transactions
--------------------------------------------------------------------------------
1. Migrate from server/orders.js in-memory array to PostgreSQL / CockroachDB.
2. Implement Optimistic Concurrency Control (OCC) or Redis Redlock for stock:
   UPDATE products SET stock = stock - $qty WHERE id = $id AND stock >= $qty;
3. Enable Write-Ahead Logging (WAL) and automated DB snapshots.

Phase 2: Enterprise Security, RBAC & Token Auth
--------------------------------------------------------------------------------
1. Implement JWT / OAuth2 authentication middleware for all order mutation endpoints.
2. Enforce RBAC validation: Ensure req.user.id === order.customer_id.
3. Inject anti-CSRF token headers on all front-end form submissions.

Phase 3: Scalable Vector Search Infrastructure
--------------------------------------------------------------------------------
1. Offload 6D vector calculations from Node.js event loop to Qdrant or Pinecone.
2. Utilize HNSW (Hierarchical Navigable Small World) indexing for sub-10ms lookup 
   across 1,000,000 SKUs.

Phase 4: Advanced Guardrail Sidecar & Observability Isolation
--------------------------------------------------------------------------------
1. Deploy NeMo Guardrails / Llama Guard 3 as an isolated gRPC sidecar container.
2. Strip internal infrastructure routing traces from public HTTP responses.
3. Stream telemetry traces directly to Databricks / Grafana Loki via OpenTelemetry 
   Collector with W3C Trace Context propagation (X-Request-ID).
